# Team contribution workflow

- Use each participant's own GitHub account; do not share credentials.
- Assign distinct, reviewable features where possible and make focused changes.
- Use descriptive commit messages such as `feat: add case evidence timeline` or `docs: add demo walkthrough`.
- Each teammate should commit their genuine work from their own account and confirm they appear in the repository history.
- Do not create fake commits or token changes to satisfy the contribution requirement.
- Review `git status` and `git diff`, run the relevant tests, and keep secrets and local database files out of commits.
- Confirm the official repository, access, deadline/time zone, and submission format with the organizers. Push all intended changes before the closing time.
